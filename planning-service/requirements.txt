# The planning service: the only service that both builds a corridor and
# reads it back, and draws the charts. vfr's own dependencies, charts
# included, come from src/requirements-charts.txt; this file lists only
# what the service needs on top. It serves no pages -- the front end is
# in web/ and ships inside webapp.
#
# PINNED, matching model-service/requirements.txt's own convention: this
# service was the one unpinned service-facing requirements file in the
# repo, and an unpinned FastAPI/pandas/etc. drifting between builds is
# exactly the kind of silent version skew that file's own comment warns
# about for a joblib artifact -- the same risk applies to any dependency
# this service and its callers both need to agree on. Pinned to what
# python:3.13-slim (this service's own base image) currently resolves.
-r ../src/requirements-charts.txt   # vfr's own list, charts included: this service draws them
fastapi==0.141.1
uvicorn[standard]==0.53.0
cachetools==7.2.0  # the service caches: bounded, and with the expiry kept by the cache rather than a timestamp per entry
boto3==1.43.98      # vfr.model_client's SageMaker Runtime path and vfr.charts' S3 publish, used only on AWS
docker==7.1.0      # routers/devservices.py starts a stopped dev service the console links to
anthropic==1.6.0   # /api/checkpoint-notes: one Claude call per checkpoint
